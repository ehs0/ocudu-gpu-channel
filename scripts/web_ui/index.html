Rank-1 multi-antenna channel emulation · workstream brief

A real 4T4R base station and a real handset exchange live traffic through a GPU-synthesised radio channel — and every run proves the channel was exactly the one we declared.

The emulator used to model each node as a single scalar stream. It now models a node as a set of antenna ports (RadioNode), so the channel between two nodes is a matrix, not a number. The base station is an unmodified OCUDU stack (4T4R) and the handset is a real srsUE held at nof_antennas = 1 throughout — none of this comes from modifying the UE. Transport is ZMQ: no RF hardware anywhere in the loop.

Downlink4 gNB TX ports → 1 UE RX port · row vector (1×4) · MISO
Uplink1 UE TX port → 4 gNB RX ports · column vector (4×1) · SIMO

How it is built

Antenna streams stay aligned

All ports of one node share a single sample epoch owned by one producer thread, and a window is emitted whole — never split, never partial. Misalignment is made impossible by the data structure rather than checked for afterwards.

broker.cpp
One kernel launch per slot

Edges into a destination row sit in a contiguous CSR range, so antenna count never multiplies launches. The grouping is built once at prepare time, not per slot.

Why this is hard: a commercial base-station stack only handles the transmitting side of multi-antenna operation. Reproducing how those four branches mix in the air — in real time, without breaking the standard procedure — requires alignment, the 1 ms budget, and provability at once. This workstream satisfies all three and automated the third as a standing gate.

Reproducibility:

bash scripts/native/run-ocudu-rank1-2x1.sh # 2×1 DL MISO + 1×2 UL SIMO bash scripts/native/run-ocudu-rank1-4x1.sh # 4×1 DL MISO + 1×4 UL SIMO

Each script brings up the 5G core (Open5GS), the gNB, the GPU broker and the UE; performs attach, PDU session and ping; captures the wire in the same run; scores the matrix; and emits a verdict. Artefacts carry source commit hashes and binary SHA-256 (source-evidence.json), so it is always determinable which code produced a given number.

Channel model coverage: TR 38.901 §7.7.2 TDL-A…TDL-E, multi-tap delay, Jakes fading, Rician LOS, spatial correlation, path loss, phase, CFO and AWGN. CPU and CUDA backends are held to agreement within 1e-3 by a standing regression test.

The downlink caveat: in the baseline configuration (CSI disabled) the srsRAN scheduler sees the cell as single-port and selects codebook [1,0,0,0], so transmit ports 1–3 carry exactly zero power. That is the stack's real behaviour, and the gate declares it explicitly via --allow-silent-source rather than hiding it — a recorded measurement, not a relaxed check. Multi-branch downlink was therefore proven separately, in the CSI-enabled configuration: 5.27e-08 with no waiver, off-diagonal share 0.081. In that run, however, attach does not complete, so the two conditions do not yet hold in the same run, and the verdict table says so.

Conditions to quote alongside any number: RTX 5090 · 23.04 MS/s · 1 ms slot (batch 23040) · CUDA backend · fixed_mimo (1 tap) + TDL chain · percentiles come from a full-slot histogram and are always quoted with n · ctest 8/8, standing GPU sequence 9/9.

Sionna RT bridge · how the live channel reaches the emulator

Sionna RT does not sit on the IQ path. It re-solves the radio geometry twice a second and hands the emulator a new set of taps; the emulator keeps shaping every sample in the 1 ms slot regardless.

The bridge is a Python process that owns the scene, moves the nodes, ray-traces every link, converts paths to taps and pushes them over the existing JSON control plane. The emulator swaps them in at a slot boundary and publishes what it actually applied. This dashboard is a third, strictly read-only observer that cross-checks the two.

What holds the two processes together

One atomic batch per iteration

Every swap in a batch is staged, not applied, until batch_commit walks them and gives all ten links the same numerical apply-slot while bumping each sequence number. A failure sends batch_abort, so a half-updated channel graph never reaches the air interface.

channel_adapter.py · send_matrix_profiles()
Applied at a slot boundary, not on arrival

The snapshot runs once per link per slot before any lane is shaped, and copies shadow to live only when the sequence number changes. A warm-up window then opens while the delay line refills, and the emulator reports it rather than hiding it.

physical_link.h · snap_physical_link()
Fading is never modelled twice

Sionna already supplies instantaneous complex path coefficients, so the bridge ships the taps with the emulator's own stochastic Jakes process switched off. What you see in the tap tables is Sionna's geometry, not a second fading model layered on top.

fading.enabled = false
The dashboard observes, it never drives

This page holds no control socket. It matches the ACK's sequence number against live telemetry from the backend, so “applied” means the backend really swapped the profile — not that a message was merely accepted.

Sample · fragment · nominal slot — definitions and estimation limits
TermMeaning in this dashboard
Sample (샘플)One complex IQ value on the time axis, per antenna port. At 23.04 MS/s one sample represents about 43.4 ns.
Fragment (조각)One variable-size process_superposition call whose size differs from the configured nominal block. It is an implementation/transport window, not a 5G NR scheduling unit.
Nominal slotExactly runtime.batch_samples contiguous time samples. In the current 23.04 MS/s, 23,040-sample configuration this represents 1 ms. It equals an NR slot only when the configured numerology also defines a 1 ms slot.
Processing callOne backend invocation. Several calls may make one nominal slot, and one call may cross a nominal-slot boundary.

Why fragments exist: the Broker deliberately makes partial progress using the common input availability and output-ring headroom of all antenna ports. Requiring a full block can strand partial data and deadlock lock-step, multi-port radios.

Proportional estimate (sample_proportional_call_time): when a call crosses a nominal boundary, its measured processing time is divided by the number of samples overlapping each nominal slot. All measured processing time is preserved, but the split is an estimate because fixed CUDA launch/transfer overhead cannot be assigned physically after the call. The metric includes only channel-backend wall time; input wait, output-room wait, pacing, and ZMQ transmission are excluded. Fragment counters are shown separately so transport fragmentation is not mistaken for compute deadline failure.

RAN KPIs by UE · gNB scheduler metrics

Served by the gNB's own remote-control WebSocket — the same feed the official GUI subscribes to. Enable it by rendering the run with OCUDU_NATIVE_GNB_METRICS=1 and starting the Web UI with --gnb-metrics-endpoint ws://127.0.0.1:8001. BLER is derived here as nok / (ok + nok) from the HARQ counters; every other value is reported by the scheduler as-is. An em dash means the scheduler reported nothing for that field in the period, including the values it signals as sentinels rather than omissions: cqi = -1 for "no CSI report", and a SINR or RSRP mean sitting on the -99.9 dB clamp floor, which is where an unreported RSRP (-inf) and a DTX-pulled PUCCH SINR both land. Two sentinels cannot be told apart from readings and are shown as-is: RI falls back to 1 when no rank was reported, and TA and PHR report 0 when unobserved.
